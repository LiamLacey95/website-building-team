# Brief 03-concept-comfyui-installer

Owner: Concept. Phase: Kit packaging. Priority: high.

Context: this repo is being published to GitHub as a kit. Someone with a fresh machine clones it, and their PM thread runs `node scripts/bootstrap.mjs`. That must be able either to **connect an existing ComfyUI** (as on this machine) or to **install ComfyUI and every model the WEB workflows need** from scratch. Read the updated `.team/PLAYBOOK.md` and your updated role file first. Only read `F:\ArtGen\ComfyUI` and `F:\ArtGen\Safeguard`; never modify them.

Deliverables in `artgen/setup/`:
1. **`models.json` manifest:** every model file the WEB workflows use (diffusion models, text encoders, VAEs, depth model, upscalers): filename, ComfyUI subfolder, official download URL (Hugging Face or GitHub release), SHA-256, size, licence, which workflows use it, and whether it is required or optional (4x-UltraSharp is optional, boards only). Find the true upstream source for each file on this machine and compute hashes from the local copies. If a file has no public source, say so and propose the nearest public equivalent.
2. **`install_comfyui.py`** (stdlib only, so it runs before any venv exists):
   - `--verify <path>`: check an existing install has ComfyUI at a compatible version and every required model with the right hash. Run this against the install on this machine.
   - `--install <dir>`: clone ComfyUI at a pinned commit (the one this machine runs, recorded in the manifest), create its venv, install CUDA torch for the detected GPU and driver, install requirements (and the manager requirements, since the launchers use `--enable-manager`), then download models with resume and hash checks.
   - `--models-only <path>`: add missing models to an existing install.
   - `--dry-run` for all of the above, with sizes and a disk-space check before downloading.
   - Test: `--verify` on this machine; a real download of one small model (RealESRGAN) into a temporary folder; `--install --dry-run` into a temporary folder. Do not run a full fresh install unless it is cheap; say in the report what you could not test.
3. **No hard-coded paths in `artgen/`:** `generate.py`, the launchers and `extra_model_paths.yaml` get the ComfyUI location from `team.config.json` (`comfyui.path`, `comfyui.python`, `comfyui.port`). Machine-specific files (launchers, `extra_model_paths.yaml`) can be generated by an `artgen/setup/configure.py` and git-ignored, with templates committed. Provide Linux `.sh` launchers alongside the `.bat` ones.
4. **`generate.py --smoke`:** one image each from WEB1, WEB3 and WEB6b, timings printed, server stopped afterwards if it started it. New teams run this on first start.
5. **`artgen/README.md`:** a "Setting up on a new machine" section, hardware tiers (12 GB as tuned; what to change for 8 GB), total download size, and the licence table. Check `BOOTSTRAP.md` section 1 and tell the PM if the disk or VRAM figures there are wrong.
6. **Bootstrap step:** give Backend (who owns `scripts/bootstrap.mjs`) the exact commands and the `team.config.json` keys you need. You may message the Backend thread directly about this.

When done: commit your paths, write `.team/reports/03-concept-comfyui-installer-concept.md`, send DONE to the PM, then wait. Concept work for how-it-works starts after Gate 1.
