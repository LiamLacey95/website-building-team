# G4 Release sign-off: review checklist

Inputs: `master` at the release-candidate commit, a deployed or local production build of `projects/<slug>/web`, the sitemap from G1, `projects/<slug>/DESIGN.md`, and all pages.
Report: `projects/<slug>/review/<brief id>-g4.md`. Every page template must be covered. Tool output: `projects/<slug>/review/out/`.
Review tool commands run from `docs/review/tools/`; the Impeccable detector runs from `tools/`.

## 1. Build the URL list
- [ ] Write `projects/<slug>/review/g4-urls.txt` with every page in the sitemap (and at least one instance of each dynamic template), plus a URL that should 404.

## 2. Automated accessibility (WCAG 2.2 AA)
- [ ] `node a11y.mjs --urls ../../../projects/<slug>/review/g4-urls.txt --viewports 390,768,1440,1920 --fail-on serious` exits 0. List moderate and minor issues.
- [ ] Check every "Needs review" (incomplete) item by hand.

## 3. Manual WCAG pass (things axe cannot check)
- [ ] Keyboard only, on every template: everything is reachable, there is no trap, the order is logical, focus is visible and not hidden by sticky headers (2.4.11), and the skip link works.
- [ ] Screen reader (NVDA with Chrome on Windows, VoiceOver on macOS) on home, one content page and every form: page title, landmarks, heading outline, link purpose, form labels, announced errors and status messages (4.1.3).
- [ ] Zoom to 200% and reflow at 320 px with no loss of content (1.4.4, 1.4.10). Text spacing override (1.4.12).
- [ ] Reduced motion is honoured; nothing flashes more than 3 times per second; carousels and animations can be paused (2.2.2).
- [ ] Targets are at least 24 px (2.5.8); dragging has a single-pointer alternative (2.5.7).
- [ ] Forms: errors are identified in text with suggestions (3.3.1, 3.3.3); no redundant entry (3.3.7); accessible authentication with no cognitive tests (3.3.8).
- [ ] Consistent help (3.2.6): contact or help links sit in the same place on every page.
- [ ] Alt text is meaningful and matches the image.
- [ ] An accessibility statement page exists.

## 4. Performance (mobile Lighthouse, every template)
- [ ] Dismiss any consent banner first (or measure a build without it), or CLS is noise.
- [ ] `node lighthouse.mjs --urls ../../../projects/<slug>/review/g4-urls.txt --runs 3` exits 0: LCP < 2.5 s, CLS < 0.1, JS < 150 KB on content pages. Check the spread lines for flaky metrics.
- [ ] Images are AVIF or WebP and responsive (check the image audits in the HTML reports).
- [ ] Record the Performance, Accessibility, Best Practices and SEO scores per template.

## 5. Design quality (Impeccable)
- [ ] From `tools/`: `npx impeccable detect --json ../projects/<slug>/web` and `npx impeccable detect <url>` at the default width and `--viewport 390x844`, for every template. Save the JSON in `projects/<slug>/review/out/`.
- [ ] Every finding is fixed or justified against `DESIGN.md`. An unjustified finding is MAJOR.
- [ ] Front-end's report shows `/impeccable audit` and `/impeccable polish` were run per page, and that the audit's top-ranked items were addressed.

## 6. Generated images: provenance and licences
- [ ] `node licences.mjs ../../../projects/<slug>/web/public/assets/generated --out ../../../projects/<slug>/review/out/g4-licences.md` exits 0. Any `FAIL` (missing sidecar, or a non-commercial model such as 4x-UltraSharp anywhere in the chain) is a BLOCKER.
- [ ] Every `NOTE` (FLUX Klein) is cleared against the client's revenue in `BRIEF.md` (free commercial use only under US$5M a year). Write the decision in the report.
- [ ] Every generated image on the site is in that folder; grep the build for image paths outside it that came from `artgen/output/`.

## 7. Links, metadata, SEO
- [ ] No broken internal or external links, and no links to localhost or staging hosts (crawl the URL list and check status codes).
- [ ] Each page has a unique `<title>` and meta description, `lang` on `<html>`, a canonical URL, and Open Graph and Twitter tags with a share image.
- [ ] `robots.txt` and `sitemap.xml` are present and correct, and there is no stray `noindex` in production.
- [ ] A favicon, app icons, and a 404 page with useful navigation exist.
- [ ] Structured data, where used, validates.

## 8. Forms and APIs end to end
- [ ] Every form: the happy path, each validation error, a server error, a double submit, and the success state. The data arrives where it should.
- [ ] Spam protection and rate limiting work; no secrets reach the client (check the bundle and the network tab).
- [ ] Security headers are present on the deployed URL.

## 9. Content proofread
- [ ] No lorem ipsum, TODOs, placeholder names or prices (grep the build output for `lorem`, `TODO`, `TBD`, `xxx`, `example.com`).
- [ ] Spelling and grammar follow one locale with a consistent voice; dates, prices and contact details are correct.
- [ ] Legal pages (privacy, cookies, terms, accessibility statement) exist and are linked in the footer; cookie consent behaves correctly.

## 10. Cross-viewport screenshots
- [ ] Each template captured at 390, 768, 1440 and 1920 (Front-end's `tools/screenshot.mjs`, saved under `projects/<slug>/screenshots/`) and checked for overflow, overlap, clipped text and broken images.
- [ ] Spot-check in Firefox and WebKit (via Playwright), not only Chrome.

## Verdict rule
PASS only when sections 2, 4, 6 and 8 have no failures, section 5 has no unjustified finding, and the manual pass found no BLOCKER or MAJOR issue.
