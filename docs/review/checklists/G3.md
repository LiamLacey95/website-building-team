# G3 Design variations: review checklist

Inputs: the three variant worktrees (folder `worktreesDir` in `team.config.json`; branches `variant/<slug>-g3-a-*`, `-b-`, `-c-`; list them with `node tools/variants.mjs list`, find one with `node tools/variants.mjs path <letter>`), their running preview URLs (`node tools/variants.mjs dev all`; port from `node tools/variants.mjs port <letter>`), the hypothesis files `projects/<slug>/variants/<letter>-<name>.md`, screenshots in `projects/<slug>/screenshots/`, `projects/<slug>/DESIGN.md`, and the G2 decision.
Report: the path your brief names; normally the packet verdict `projects/<slug>/gates/G3-design/review.md` (else `projects/<slug>/review/<brief id>-g3.md`) with the scorecard below. Tool output: `projects/<slug>/review/out/` (the tools default there when `activeProject` is set).

## Automated checks per variation (home plus the key interior page)
Run from `docs/review/tools/`:
- [ ] `node a11y.mjs <urls> --viewports 390,768,1440,1920`. Any critical or serious violation is MAJOR.
- [ ] `node lighthouse.mjs <urls>` (mobile) for an indicative number. This is not yet a gate, but flag anything far off budget.
- [ ] `node contrast.mjs --palette <palette.json>` if the palette changed since G2.

## Impeccable detector (independent evidence)
Run from `tools/`, where the CLI is pinned (never from the repo root):
- [ ] On the source: `npx impeccable detect --json <worktree>/projects/<slug>/web > ../projects/<slug>/review/out/g3-<letter>-detect.json`.
- [ ] On the running page at two widths: `npx impeccable detect <url>` and `npx impeccable detect --viewport 390x844 <url>`.
- [ ] Exit 0 means clean and 2 means findings. Compare the results with the "detect results" in the variation's hypothesis file. Every finding must be fixed or justified there. An unjustified finding is MAJOR, and results that don't match the variant file are MAJOR (the evidence is stale).
- [ ] Check justifications on their merits: "the direction calls for it" must point to `DESIGN.md` or the chosen direction, not just assert it.
- [ ] Advisory findings (for example em-dash overuse) are listed but never block.
- [ ] The variant file records the `/impeccable critique` result and what was fixed. Optionally run `/impeccable critique <target>` yourself on one section for a second opinion.

## Responsive (screenshots at 390, 768, 1440, 1920)
- [ ] No horizontal scroll at any width, and no clipped or overlapping text.
- [ ] Navigation works at mobile width and the menu is reachable by keyboard.
- [ ] Tap targets are at least 24x24 px (WCAG 2.5.8), ideally 44 px.
- [ ] Line length is about 45 to 80 characters at desktop, and images are cropped sensibly per breakpoint.
- [ ] Content reflows at 320 px CSS width (1.4.10).

## Creativity score (required: `creativity.md`)
- [ ] Score every variation on all five axes **on the running site** (390 and 1440 px, keyboard, reduced motion), before reading its variant file. Then compare with the team's self-assessment.
- [ ] Memorability sentence per variation; three different sentences.
- [ ] Report weighted and Awwwards-weighted scores side by side. The recommended variation needs weighted ≥ 7.0, no axis below 6, and a passing memorability check. If the safest variation scores lowest on C, say so.
- [ ] AI-generic tells from the detector run above feed the C, S and D penalties in `creativity.md`.

## Visual design
- [ ] There is one clear primary action per screen, and the hierarchy holds up in a squint test.
- [ ] Spacing and type scale are consistent and match `DESIGN.md` and the chosen direction's style tile.
- [ ] It is faithful to the G2 direction: palette, type and imagery.
- [ ] No lorem ipsum (playbook: none at G3 or later); copy is realistic.

## Nielsen heuristics (note violations only)
- [ ] Visibility of system status, match with the real world, user control and freedom, consistency, error prevention, recognition over recall, flexibility, minimalist design, error recovery, help and documentation.

## Accessibility smoke test (manual, 5 minutes per variation)
- [ ] Tab through the home page: the focus indicator is visible on every element, the order is logical, and a skip link is present.
- [ ] One h1 per page, no skipped heading levels, and landmarks (header, nav, main, footer) are present.
- [ ] Motion respects `prefers-reduced-motion`.

## Hypothesis
- [ ] Each variation's file states the hypothesis it tests (for example "an editorial layout increases scroll depth"), the persona it serves and the trade-off, and the three test different hypotheses.
